# Tests without test doubles

The landmines lint rules (`.oxlintrc.json`) refuse `vi.mock`, `vi.fn(impl)`, `mockReturnValue` and the like, `vi.stubGlobal`, and patched globals. Use the real module. Use MSW for the network. A spy may only watch. The rules also refuse fixed sleeps, retries and raised timeouts. In test code they refuse comments and annotated return types. Put the reasons in the commit message.

Lint each file you touch: `pnpm exec oxlint <files>`. It prints nothing when the file is clean.

## Where a test runs

`vitest.config.mts` picks the environment from the file name, so do not add `// @vitest-environment` comments. Delete them when you touch a file: with every comment removed, the suite gives the same results.

- `*.int.test.ts` and `*.unit.test.ts` run in **node**, like the server code they test.
- `*.unit.test.tsx` runs in **jsdom**.
- The `domTs` and `nodeTsx` lists in the config hold the exceptions. A `.ts` test that needs a DOM goes in `domTs`.

## Other patterns

- **A sleep that waits for a library's `setTimeout(0)`** (for example, Radix attaches its outside-click listener this way). Fake `setTimeout` around the trigger, run the one pending timer, then restore real timers. Check that the test fails without the timer run. Call `vi.useRealTimers()` in `afterEach` too. See the dialog exemplar.
- **Callback props.** `vi.fn()` with no implementation only records calls, so it is allowed. `vi.fn(impl)` is not.
- **Watching a real module.** `vi.mock(path, { spy: true })` keeps the real code and records calls. The rule allows it (checked with a scratch test: lint clean, real result, calls recorded).
- **Node 26 `localStorage`.** The config starts workers with `--no-experimental-webstorage`, so jsdom's real storage is the global. Do not redefine it.

## Not solved yet

- **jsdom has no `matchMedia`, `ResizeObserver` or `IntersectionObserver`.** The setup still installs a `matchMedia` stand-in that matches nothing. That is the one landmines error left in `vitest.setup.ts`. About 23 test files stub `ResizeObserver` and 3 stub `IntersectionObserver`. Without a real implementation, those stubs cannot go, so those files cannot lint clean yet. The same gap blocks:
  - `@/components/calendar/ui/use-narrow`. Its hooks read a container-query flag with `getComputedStyle` and a `ResizeObserver`. jsdom does no layout and has no `ResizeObserver`.
  - Phone layouts behind `@/lib/use-narrow` (`matches: true`), and the reduced-motion branch behind motion's `useReducedMotion`. jsdom cannot report a narrow viewport or a motion preference.
- **happy-dom (measured, not adopted).** Its source has a `matchMedia` that evaluates queries against a settable viewport and a reduced-motion setting, and `ResizeObserver` and `IntersectionObserver` classes that never fire (read, not run here). With all `.unit.test.tsx` files and the `domTs` list on happy-dom, 6 tests in 5 files fail:
  - `session-drawer` (2)
  - `avatar-fallback` (the image `data-loading` state)
  - `week-spans`
  - `analytics-sdk`
  - `space-head-actions` (its `offsetParent` stub cannot install; without the stub, the test passes on happy-dom)

  Moving to happy-dom needs those fixed first. It also needs `happy-dom@21.0.4` as a devDependency. The lockfile already resolves that version.

- **`fetch` stubs (12 files) need MSW.** MSW is not installed. Add it once, in one commit, so that several branches do not each change the lockfile. Start the server with `onUnhandledRequest: 'error'`.
- **`next-intl/server`** (from reading the package and Next's source, not run). The real `getTranslations` needs next-intl's `react-server` build and `next-intl/config` pointed at `src/i18n/request.ts`. That file imports `next/root-params`, which Next's compiler replaces and which throws when imported anywhere else. A copy of the request config just for tests would be a fake. The fix belongs in production code: keep the parts a test needs (messages, formats, time zone for a locale) in a module that does not import `next/root-params`.
- **The cron route** (`src/app/(frontend)/api/cron/spaces/route.ts`). An int test would run the real digest and purge jobs against the shared database. Let the route receive the job as a value, and the test can pass a real, harmless job.

## Rejected

- Installing the missing browser APIs where lint cannot see them: jsdom's `beforeParse`, a custom environment file, or a non-test module. They are still stand-ins.
- Replacing a sleep with `setImmediate`, `requestAnimationFrame` or a retry loop. Each one guesses the time in a different way.
- Aliasing `next-intl/config` to a test-only request config.
- Making `@/env` tests set `window` to `undefined`. They run in node instead.
