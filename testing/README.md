# Tests without test doubles

The landmines lint rules (`.oxlintrc.json`) refuse `vi.mock`, `vi.fn(impl)`, `mockReturnValue` and the like, `vi.stubGlobal`, and patched globals. Use the real module. Use MSW for the network. A spy may only watch. The rules also refuse fixed sleeps, retries and raised timeouts. In test code they refuse comments and annotated return types. Put the reasons in the commit message.

Lint each file you touch: `pnpm exec oxlint <files>`. It prints nothing when the file is clean.

## Where a test runs

The file name alone picks the runner. Do not add `// @vitest-environment` comments.

| Name                   | Project   | Runs in                                             | Use it for                                                                                                                     |
| ---------------------- | --------- | --------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| `*.int.test.ts`        | `node`    | Node, with the database                             | Payload, server actions, routes                                                                                                |
| `*.unit.test.ts(x)`    | `node`    | Node                                                | Pure code, server code, emails rendered to HTML                                                                                |
| `*.dom.test.ts(x)`     | `dom`     | jsdom                                               | Components that need no layout, no observers and no media queries                                                              |
| `*.browser.test.ts(x)` | `browser` | Headless Chromium (Vitest browser mode, Playwright) | Components that need layout, `ResizeObserver`, `IntersectionObserver`, `matchMedia`, container queries, popovers or animations |

`pnpm exec vitest run` runs all three projects. `pnpm test:unit` runs everything except `*.int.test.ts`. Run one project with `--project browser`. The browser project uses the Chromium that Playwright caches (`pnpm exec playwright install chromium` if it is missing).

## Move a test from jsdom to the browser

1. `git mv x.dom.test.tsx x.browser.test.tsx`.
2. Delete the stand-ins for what Chromium has: `ResizeObserver`, `IntersectionObserver`, `matchMedia`, `scrollIntoView`, `getAnimations`, `animate`, `showPopover`, and calls to `stubPopupDom` or `stubMatchMedia`. In Chromium a plain assignment such as `globalThis.ResizeObserver = class {}` replaces the real one, so a leftover stub silently turns the browser off.
3. For a phone layout, call `await page.viewport(390, 844)` (`import { page } from 'vitest/browser'`). For a reduced-motion branch, call `await emulateMedia({ 'prefers-reduced-motion': 'reduce' })` from `media.test-utils` (checked with a scratch test, no exemplar yet). The setup puts the 1280 × 800 viewport and the media back after each test.
4. Delete mocks of `@/lib/use-narrow` and `@/components/calendar/ui/use-narrow`. The real hooks read the real viewport and the real container queries. Real CSS also hides things: a `getByRole` that found an element in jsdom can miss it in Chromium when the stylesheet hides it at that width. Size the viewport to the layout you test.
5. To watch a call, use `vi.spyOn(object, 'method')` with no implementation. It calls through.
6. Change the URL with a relative URL (`history.replaceState(null, '', '#x')`). The test runs in an iframe of the Vitest page. Do not send it to another path.
7. A test that reads a file from disk (`node:fs`) checks source, not rendering. Move that test to a `*.unit.test.ts`.
8. Run the file, then lint it.

A browser test must not import server code, even through a component. If one file reaches `payload` or `@payload-config`, Vite's dependency scan fails and every browser test fails with it. See [Components that call server actions or Payload](#components-that-call-server-actions-or-payload).

Exemplars: `src/components/course/course-syllabus.browser.test.tsx` (`ResizeObserver`), `src/app/(frontend)/[locale]/study/[slug]/course-view-time.browser.test.tsx` (`IntersectionObserver`), `src/components/person-profile-block.browser.test.tsx` (`matchMedia`, a phone), `src/components/calendar/ui/calendar-views.browser.test.tsx` (container queries, server markup and hydration), `src/components/calendar/ui/use-narrow.browser.test.tsx` (the calendar's width flags).

## The network: MSW

Call `mockNetwork(...handlers)` once at the top of the file or the `describe`. Add per-test handlers with `network.use(...)`. They reset after each test.

- Node (`*.unit.test.ts`, `*.int.test.ts`, `*.dom.test.tsx`): `mockNetwork` from `msw-node.test-utils`.
- Browser: `mockNetwork` from `msw-browser.test-utils`. The browser project serves `node_modules/msw/lib` as its public folder, so the worker file never enters `public/` or the production build. The app's own `public/` files are not served in browser tests.

Both start MSW with `onUnhandledRequest: 'error'`, and both fail the test in `afterEach` for each request that no handler answered, even when the code caught the error. So a test proves that a request did not happen by having no handler for it. Requests for scripts, styles and other assets (MSW's `isCommonAssetRequest`) are not counted. Answer with `HttpResponse.json`, `HttpResponse.html`, `new HttpResponse(null, { status: 302, headers })`, or `HttpResponse.error()` for a network failure.

- In jsdom, a relative URL such as `fetch('/api/x')` resolves against `http://localhost:3000/`, and a handler for `/api/x` answers it (checked with a scratch `.dom.test.tsx`).
- An int test that also calls a local service the test owns (Typesense, RustFS) lets those requests through by origin: `http.all('http://localhost:8108/*', () => passthrough())` (checked against the local Typesense). Do not pass through a whole public origin.

Exemplar: `src/lib/event-place.unit.test.ts`.

## Components that call server actions or Payload

A browser test cannot load a server action or Payload, and a jsdom test can only reach them through `vi.mock`. **Default: pass the action in as a prop.**

1. The component takes the effect as a prop, typed by what it needs: `publish: (form: FormData) => Promise<SpacesWriteState>`. Import only types from the action's module.
2. A small connected component, in its own file, binds the real action: `<ScheduleOfferDialog {...props} publish={(form) => postCreateAction({ status: 'ok' }, form)} />`. A server component can pass the action straight down instead. Keep an existing lazy boundary: load the connected file where the plain one loaded before. When a hook imported the action statically, three other jsdom files started to load Payload.
3. The browser test plays the host: it passes a plain function that records its input and answers as the action does. This is the component's own interface, the same as the calendar's `onSave`. It is not `vi.fn(impl)`.
4. The action's own behavior gets an int test with `runInRequest` and the real Payload. The wiring between them is e2e.

Why a prop, though AGENTS.md calls a parameter with one caller surplus: the action is the component's one effect on the world, and the prop is the only way the component can load in a browser at all. Moving every assertion to an int test or e2e instead loses the component's own states (busy, failed, retried), which only a rendered test can see.

Exemplar: `src/components/space/schedule-offer-dialog.tsx`, `connected-schedule-offer-dialog.tsx`, and `src/components/admin/schedule-offer-dialog.browser.test.tsx`.

## Other patterns

- **A sleep that waits for a library's `setTimeout(0)`** (for example, Radix attaches its outside-click listener this way). Fake `setTimeout` around the trigger, run the one pending timer, then restore real timers. Check that the test fails without the timer run. Call `vi.useRealTimers()` in `afterEach` too. See the dialog exemplar.
- **Callback props.** `vi.fn()` with no implementation only records calls, so it is allowed. `vi.fn(impl)` is not. When the component needs the callback's answer, pass a plain function that records its input and returns the answer, as the host does.
- **Watching a real module.** `vi.mock(path, { spy: true })` keeps the real code and records calls. The rule allows it (checked with a scratch test: lint clean, real result, calls recorded).
- **Literal types without a return annotation.** Write `({ ... }) satisfies CalendarItem` where the annotation used to be. Without it, `tone: 'yellow'` widens to `string`.
- **Node 26 `localStorage`.** The config starts workers with `--no-experimental-webstorage`, so jsdom's real storage is the global. Do not redefine it.

## Not solved yet

- **Three jsdom files still need `matchMedia`**: `src/actions/space-calendar-edit.dom.test.tsx`, `src/components/space/space-calendar.dom.test.tsx` and `src/components/space/schedule-block.dom.test.tsx`. They render components that import server actions, so they cannot move to the browser yet. They call `stubMatchMedia()` from `popup-dom.test-utils`. Give those components their actions as props, move the files to the browser, then delete `stubMatchMedia` and, when no `.dom` file calls it, `stubPopupDom`.
- **Files moved to the browser with their stubs.** Eight files moved in the matchMedia commit (`calendar-edit`, `-marked`, `-menu`, `-read-only`, `-reload`, `-save-bar`, `-view` and `movie-block`) still have their `ResizeObserver`, `stubPopupDom`, `vi.mock` and comment lines. They pass with them, but a stub there hides the real API. Delete them per the steps above.
- **`next-intl/server`** (from reading the package and Next's source, not run). The real `getTranslations` needs next-intl's `react-server` build and `next-intl/config` pointed at `src/i18n/request.ts`. That file imports `next/root-params`, which Next's compiler replaces and which throws when imported anywhere else. A copy of the request config just for tests would be a fake. The fix belongs in production code: keep the parts a test needs (messages, formats, time zone for a locale) in a module that does not import `next/root-params`.
- **The cron route** (`src/app/(frontend)/api/cron/spaces/route.ts`). An int test would run the real digest and purge jobs against the shared database. Let the route receive the job as a value, and the test can pass a real, harmless job.

## Rejected

- Installing the missing browser APIs where lint cannot see them: jsdom's `beforeParse`, a custom environment file, or a non-test module. They are still stand-ins. The browser project replaces them.
- happy-dom. Its `ResizeObserver` and `IntersectionObserver` never fire (read in its source, not run), and 6 tests in 5 files failed on it (measured).
- Replacing a sleep with `setImmediate`, `requestAnimationFrame` or a retry loop. Each one guesses the time in a different way.
- Aliasing `next-intl/config` to a test-only request config.
- Making `@/env` tests set `window` to `undefined`. They run in node instead.
- Rerunning a browser test after "Vite unexpectedly reloaded a test". The browser project scans every browser test for dependencies before it starts (`optimizeDeps.entries`, `force: true`), so the reload does not happen.
