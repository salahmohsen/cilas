# 0010. Private Spaces search is mediated by the server

Accepted for implementation, 2026-10-28. Disabled until the rollout checks below pass.

Members search posts and comments across currently readable spaces, or select any subset of those spaces, including none. The existing public search stays separate. This supersedes the Postgres-only search choice in the original Spaces design. The [research and release matrix](../superpowers/specs/2026-10-28-private-spaces-search-research.md) explains the alternatives and source references.

## Read boundary

`POST /api/spaces-search` accepts a strict query, an optional array of numeric space IDs (`spaces`, omitted means all; empty means none), relevance/newest/A–Z sort, locale and authenticated cursor. The original single numeric `space` remains accepted for existing callers; combining both selection formats is rejected. Selections are deduplicated, sorted and checked against current permissions. Empty and one-character queries browse readable content, as in public search; arbitrary engine wildcards are still rejected. Request bodies remain bounded at 64 KiB, with at most 2,000 selected IDs. A separate strict options request derives labels from current permissions. It accepts no Typesense parameters or multi-search body. Anonymous, expired and logged-out sessions are refused. Payload 3.91's installed JWT strategy re-reads the user and checks persisted sessions, so demotion and person-link changes use current records.

Postgres supplies the permission envelope on every request. Request context carries a private memoization scope through Payload's copied contexts. Introduction IDs and introduction-comment relationships are bound to their space IDs, including in the shared collection access rule. Existing admin access through Off/Trial is preserved. Empty permissions stop before the index call. Every selected space must be authorized; selection is applied after candidate validation, while the complete permission predicate always guards the engine query.

The private engine returns IDs, routing metadata and a content fingerprint only. Both highlight formats are disabled, curations are disabled, curated hits are filtered, and engine caching and per-query analytics are disabled. Candidate content is batch-loaded with the authenticated user and explicit `overrideAccess: false`. Current relationships, the permission envelope, display state and projection revision are checked again. Only current database text reaches the response. The response now includes `aggregates: { total, facets: [{ id, found }] }` only after exhausting a bounded live-validated scan. Facets count all readable spaces independently of selection; total counts only selected matches. Stale revisions, deleted threads and inaccessible candidates never count. These are validated query aggregates, never raw Typesense counts. An incomplete/cutoff scan returns `aggregates: null`; the client omits unknown counts and keeps those options enabled instead of treating them as zero. Timings and suggestions remain excluded. This supersedes the initial no-aggregate contract to support the requested shared filter behavior.

Deleted items and whole deleted-post threads are excluded. A live reply beneath a deleted comment remains eligible. A reply with a missing/unreadable parent, a parent in another thread/space, or a parent which is itself a reply is excluded, matching the current two-level thread display. A hard-deleted parent whose relation has been nulled produces a top-level comment, as in normal display. Results open the owning post; comment-specific scroll targeting is outside this version.

One record per item contains its own Markdown/plain text and event title, numeric routing fields, update timestamp and a SHA-256 projection revision. Link targets and bare URLs are stripped. Author identities, memberships, voter identities, file contents and file URLs are excluded. Attachment text extraction and author search remain deferred. Result thumbnails are loaded separately from live, access-checked `space-files`, scoped to validated post/comment attachments or an event cover and the same space. Only existing authenticated Payload file routes are returned; storage URLs and file metadata remain outside the search index. Missing or unreadable images use the shared post/comment icon fallback. Revisions include transformation version and the parent-comment relationship. Stale revisions suppress the entire match, including edited-away phrases.

Responses and errors use `private, no-store`, `Vary: Cookie, Authorization` and no-cache headers. Browser requests use no-store, debounce for 250 ms, abort previous requests and reject stale responses. Private text is rendered as React text, never HTML. Opening/focusing/returning to the search panel refreshes permissions; hiding the document clears private options and results. Logout broadcasts a local and cross-tab invalidation event and closes open search. No private data enters InstantSearch or its cache. Private queries are not passed to public search while the private scope is selected. Both tabs use the same unchecked-facet state and filter components: all options start checked, arbitrary subsets and none are representable, and Clear restores all. Validated per-space counts stay mounted when only selection changes, but are discarded on query/account/permission/scope changes. Filter intent can survive a refresh only for the same freshly authorized account; result data is always cleared. Checked options with a proven zero count are disabled, while unchecked zero-count options remain enabled, matching public search.

## Work and pagination bounds

A page contains at most 20 validated rows. Candidate batches contain 40 rows, each row-page and aggregate pass scans at most 200 candidates (sharing validated batches when offsets coincide), engine cutoff is 500 ms and the application checks a 3-second scan deadline between batches. Each engine request has a 2-second transport timeout and no retries. Database/network waits can exceed the scan deadline; this is a work budget, not a strict wall-clock SLA. Options fail closed beyond 2,000 admin-visible spaces. Global A–Z ordering is computed over the exhaustive validated match set; an incomplete aggregate scan cannot safely provide global A–Z results and returns an incomplete state instead. Large queries may therefore remain incomplete under the existing work budget; this change does not claim exhaustive counts beyond that bound.

`hasMore` requires a 21st validated result. Its cursor resumes at that extra candidate. An exhausted scan budget reports incomplete results rather than an authoritative empty set. Cursors have a five-minute lifetime, a 10,000-offset ceiling, and an HMAC binding to account, current role/person, query, selection, sort, locale, active generation and effective permission envelope. Changed bindings return 409. Offset pagination during live writes is best effort, not a snapshot.

Postgres rate counters allow 45 requests/account/minute, 180/abuse bucket/minute and 600 globally/minute. Until a trusted reverse-proxy client-address contract is installed, all network traffic uses one conservative shared abuse bucket. Browser-controlled forwarding headers are ignored. This intentionally limits aggregate traffic to 180/minute for now. The worker expires old counter rows. Queries and IP addresses are not persisted.

## Durable synchronization and fencing

The migration creates raw Postgres outbox, state and rate tables. Post/comment hooks insert IDs through the active Payload transaction. They refuse writes without a transaction. They perform no HTTP calls. Apply the migration before starting app instances containing these hooks, even while the UI flag is off.

A separately scheduled worker claims a Postgres advisory lock and records a durable writer token. Ordinary work reads committed state and uses physical-generation writes, full-document imports, idempotent deletions, retries and capped exponential backoff. Hard-deleting a comment transactionally queues its direct children before Postgres nulls their parent relationships. A post's ordinary edit updates that post only; deleting it removes its indexed thread. Restoring a post enqueues a thread refresh. Comment changes do not repeatedly reindex the entire thread.

The advisory lock alone cannot fence an engine request left in flight after a database connection loss or a transport timeout. Therefore an interrupted/uncertain writer leaves its token durable and subsequent ordinary workers refuse to run. Recovery is an explicit rebuild into a new unique generation. Every write checks ownership before and after its engine request. Postgres holds the authoritative active generation; the Typesense alias is a convenience, not the serving authority. A late old write or alias update cannot change the serving generation. A recovered writer can only publish through a token-checked Postgres update.

Rebuild holds the same writer lock, keeps the outbox from before scanning, scans posts and their comments in bounded batches, captures actual committed queue rows, replays them, updates the alias, publishes the generation in Postgres, then acknowledges only those exact rows. It never discards by sequence watermark, since sequence allocation order is not commit order. Later commits remain queued. A crash after publication causes replay. A lost alias acknowledgement keeps the serving generation and backlog intact and retains the uncertain generation. Rebuild refuses a captured backlog larger than 10,000 rows. There is no private startup rebuild.

SDK 3.1.1 array imports throw on partial row failure. Known import/4xx failures retain the event with backoff. Unknown failures require generation recovery. Neither raw import errors nor queries, bodies or credentials are logged. Superseded generations are removed with the explicit coordinated `prune` command. Until pruned, they remain private copies. The same retention policy must cover engine disks, snapshots and backups.

## Rollout prerequisites

1. Review the diff and apply `20261028_120000_private_search` against the existing migrated database before app rollout. The fresh historical migration chain currently fails in `20261018_174136_drop_about_page`, which reads current schema before `site_settings_rels` exists. This feature does not repair that historical migration. The disposable tests initialize current Payload schema, then apply this feature's real migration.
2. Run a dedicated private Typesense **30.2** service alongside the existing public engine in the CILAS Typesense Compose deployment, matching `docker-compose.search-test.yml`, on the private service network where practical. Keep `--enable-access-logging=false`, `--enable-search-logging=false`, and `--log-slow-requests-time-ms=-1`; do not enable query analytics for this collection. Do not expose management routes through an unrestricted proxy.
3. Audit the existing public browser key. Its only action must be `documents:search`, with `^(courses|articles|people)(_[0-9a-f]{8})?$` collection scope. The existing server-side `TYPESENSE_API_KEY` should likewise be restricted to the public collections and their required legacy cleanup names rather than remain a root key. Public schemas must never reference private collections. Do not add Spaces to `SEARCH_COLLECTIONS`.
4. Provision separate server-only keys. `TYPESENSE_PRIVATE_SEARCH_KEY` needs `documents:search` on `^spaces_search_[a-f0-9]{32}$`. `TYPESENSE_PRIVATE_WRITE_KEY` needs `collections:*`, `documents:import`, `documents:delete`, `aliases:*` on `^spaces_search(_[a-f0-9]{32})?$`. Real-engine tests exercise these write permissions and the read-only search key. Do not reuse the public key or place either private key in a `NEXT_PUBLIC_*` variable. The existing public search configuration is still required to open the site search panel.
5. Complete the credential audit and set server-only `PRIVATE_SPACES_SEARCH_KEYS_VERIFIED=true`; this is required for maintenance writes and, together with the feature flag, for private reads. Run `NODE_OPTIONS='--conditions=production' pnpm exec tsx scripts/private-search.ts rebuild` with the intended server environment. In the production image use `node --conditions=production /app/maintenance/run.mjs rebuild`; the Dockerfile packages an independent CLI dependency tree. `status` reports sanitized queue health. Then schedule `work` frequently enough for the measured queue arrival rate. Each invocation handles at most 100 events. Monitor sanitized `{processed, failed, recoveryRequired}`, queue age/attempts and nonzero exit status. A retained writer token or uncertain write requires `rebuild`, not manual token deletion. Stop superseded worker processes before recovery.
6. Run `prune` after successful rebuilds and during retention maintenance. It removes every superseded `spaces_search_<uuid>` generation, including uncertain generations. Active requests into removed generations can fail safely and retry. Retain the current generation. Apply retention limits to backups as well.
7. Exclude `/api/spaces-search` from proxy/CDN/service-worker caching and request-body/access logging. Keep database connections on the primary. Validate trusted-proxy/rate-limit choices and load on the actual VPS before enabling `PRIVATE_SPACES_SEARCH=true`. It defaults to false. Permission revocation is evaluated during server validation; already downloaded text cannot be recalled.

## Verification

Run `./scripts/test-private-search.sh`. It starts only its explicitly named disposable Postgres, Typesense and local S3 test services, exports dummy local credentials, initializes schema and migration, runs the private contract tests and existing Spaces integration suites, reports container resources, then removes its containers. The schema is reset between private and existing suites only in this dedicated disposable database. It never loads the default compose app or touches localhost:5433. Ports 55439, 18109 and 19000 must be free. The cached MinIO image digest is pinned; its registry currently refuses new pulls, so another host may need a preloaded image or `SEARCH_TEST_S3_IMAGE` pointing at an available compatible image. This storage service is for existing upload integration tests only. The bootstrap accepts only its exact disposable database URL.

The tests use real engine credentials, search filters, curations, partial imports, alias publication and Postgres transactions. They terminate the actual writer database connection while an import is delayed, then prove that generation recovery fences the late write. Client tests cover abort races, account changes, logout invalidation and escaped text. The research matrix remains the release checklist; these tests do not establish a production concurrency capacity or Arabic relevance quality across representative member content. Broader human relevance review, proxy/CDN configuration, on-host load/resource measurements and retention ownership remain rollout work.

The [production operations runbook](../private-spaces-search-operations.md) records the inspected topology, separate private endpoint variables, preserved public engine, credential cutover, prepared Dokploy jobs, exact remaining rollout gates and the large-corpus parity limitation.
